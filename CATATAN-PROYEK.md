# Catatan Proyek – Website ExtraCourse

Ringkasan untuk melanjutkan pengembangan di chat baru. Baca file ini dulu sebelum mengubah apa pun.

## Arah proyek

- Website ini fokus pada **game dan aktivitas belajar yang menyenangkan**.
- Data administratif (absensi, pendaftaran lengkap, laporan orang tua) **tidak** ada di sini; semuanya dikelola di spreadsheet.
- Pengguna: siswa les ExtraCourse dengan jenjang SD, SMP, SMA, Kuliah S1, Kuliah S2, dan Umum.

## Teknologi

- HTML/CSS/JS statis, tanpa build step. Firebase **9.23.0** dari CDN gstatic.
- Firebase Auth (email/password) dan Firestore, project `extra-course-d02c2`.
- Konfigurasi bersama ada di **`ec-common.js`**: config Firebase, `ADMIN_EMAIL`, daftar jenjang (`LEVELS`), helper nama pengguna, helper minggu peringkat (WIB), `shortName`, `escapeHtml`, dan `friendlyAuthError`.
- Aturan keamanan ada di **`firestore.rules`**, dengan penjelasan di **`KEAMANAN.md`**. Aturan **harus ditempel manual** ke Firebase Console → Firestore → Rules setiap kali berubah.
- **Nomor versi file** (sejak 3 Nov 2026): semua rujukan file lokal memakai tanda versi yang sama, mis. `game-ui.css?v=2026-11-03`, `src="notifications.js?v=..."`, `import ... from "./ec-common.js?v=..."` (juga di dalam file .js). Tujuannya agar browser tidak mencampur file lama & baru. **Sebelum setiap commit yang mengubah file website: `node versi.mjs`** (ganti versi ke tanggal hari ini WIB; dijalankan lagi di hari yang sama → `-2`, `-3`), lalu `node versi.mjs --cek` (harus "Semua rujukan memakai versi yang sama"). Tanda harus sama di semua tempat: satu file dengan dua tanda berbeda dimuat dua kali. Firebase CDN dan tautan antarhalaman tidak diberi versi. Aturan kerja sesi ada di `CLAUDE.md`.
- **Cara rilis (push ke main):** tugas terjadwal "Paket soal mingguan" mem-push `paket-otomatis/<Senin>.json` langsung ke `main` setiap **Minggu 18.43 WIB**, jadi `origin/main` sering sudah punya commit baru dan push langsung akan ditolak. Setiap rilis: `git fetch origin` → susun ulang commit rilis di atas `origin/main` (`git rebase origin/main`, atau untuk rilis sebagian: buat cabang dari `origin/main` lalu `git cherry-pick <commit>`) → `node versi.mjs --cek` (harus "Semua rujukan memakai versi yang sama") → baru push. Jangan force-push. Rilis dipisah per fitur: aturan 2 minggu 29 Nov 2026 malam (aturan Firestore gabungan 2 minggu + event ditempel sekali sebelumnya), kode event Musim Liburan Tahap 1 30 Nov 2026 malam setelah aturan 2 minggu terbukti jalan.
- Folder `Claude outputs/` = file paket cadangan milik pemilik, tidak di-commit (`.gitignore`).

## Paket soal (bank soal dari guru)

- Dibuat admin di tab **Paket Soal**: judul, jenis, jenjang (atau Semua jenjang), **level 1–5** (`tier`, 1 = paling mudah; `PACK_TIERS` di `ec-common.js`), daftar soal ditempel satu per baris. Daftar paket admin bisa dicari & difilter jenjang dan **pembuat** (Admin / nama guru; kolom Pembuat). Guru juga bisa membuat paket di `guru.html` (maks. 30 soal; admin 200).
  - **Status** (`packStatus` di `ec-common.js`, label `PACK_STATUS_LABEL`): Draf (`draft: true`, selalu `active: false`, tanpa `publishedAt`), Terjadwal, Terbit, Nonaktif. Draf tidak pernah terlihat siswa (semua pemuat paket memakai `active == true`) dan aturan melarang `active` + `draft` bersamaan. Admin yang mengaktifkan/menerbitkan draf guru → `draft: false`. Pemilik (`ownerId`) tidak pernah berubah; paket tanpa `ownerId` = paket admin (semua paket lama).
  - `kosakata`: `kata = arti` (jawaban alternatif dipisah `/`, mis. `big = besar / luas`) → item `{q, a}`
  - `verb`: `eat, ate, eaten = makan` → item `{v1, v2, v3, arti}`; bentuk ganda dengan `/` (mis. `learn, learnt / learned, learnt / learned = belajar`)
  - `kalimat`: satu kalimat per baris, 2–20 kata → item `{text}` (dipakai Susun Kalimat)
  - Maks. 200 soal per paket. Pengurai teks: `parsePackText` / `packToText` di `ec-common.js`.
  - **Jadwal terbit** (kolom Terbit: Sekarang / Jadwalkan / Tidak diubah): `publishedAt` boleh di masa depan. Saran jadwal = Senin depan 07.00. Paket terjadwal disaring di `loadQuestionPacks` (game-scores.js) sehingga tidak tampil di game, lonceng, atau Beranda sampai waktunya; aturan Firestore menolak skornya sebelum `publishedAt`. Admin: status "Terjadwal" + tanggal. Mengaktifkan lagi paket terjadwal tidak mengubah jadwalnya. (Isi paket terjadwal tetap bisa dibaca lewat konsol oleh siswa yang sangat paham teknis; hanya tampilan, tidak bisa diberi poin.)
- **Paket otomatis mingguan** (sejak 21 Nov 2026): tugas terjadwal Claude tiap **Minggu ± 19.00 WIB** membuat `paket-otomatis/<Senin>.json` (4 paket kosakata × 10 soal: SD, SMP, SMA, Semua jenjang; satu tema; level bergilir 1→2→3) lalu push ke `main`. Workflow `.github/workflows/unggah-paket.yml` menjalankan `scripts/unggah-paket.mjs` (firebase-admin, kunci di secret `FIREBASE_SERVICE_ACCOUNT`) dan menyimpan paket sebagai paket admin, ID `auto-<Senin>-<jenjang>`, **terjadwal Senin 06.00 WIB**. Paket yang sudah terbit tidak diubah lagi. Aturan isi & format: `paket-otomatis/PANDUAN.md`. Tanpa perubahan `firestore.rules` (firebase-admin melewati aturan).
- **Rencana rilis yang disarankan**: 2–3 paket baru per jenjang tiap Senin (+1 Kamis jika sanggup), memakai jadwal terbit.
- **Hanya skor dengan paket soal yang menambah poin.** Latihan dengan kata sendiri tetap tersimpan (riwayat), tetapi tidak dihitung.
- Jika satu paket dimainkan berkali-kali dalam seminggu, yang dihitung **hasil terbaik** per siswa per paket (`weeklyPoints` di `ec-common.js`, dipakai `leaderboard.html` dan `user-dashboard.html`).
- **Batas 2 minggu per paket** (mulai minggu `PACK_LIMIT_FROM_WEEK` = 2026-11-30, `PACK_POINT_WEEKS` = 2 di `ec-common.js`): setiap paket memberi poin kepada seorang siswa hanya di 2 minggu kalender pertama ia memainkannya (minggu `packStart` + minggu berikutnya). Minggu ke-3 dst. = latihan: skor tetap tersimpan (juga tampil di Hasil guru), tetapi 0 poin dan tidak menambah jumlah "Paket", jadi juga 0 koin, 0 XP tier, tanpa pengaruh ke Musim/bonus/rekap (semuanya dari `weeklyPoints` lalu `weeklyResults`). Pengecekan: `isPracticeWeek(packStart, week)`; `scorePoints` = 0 untuk skor latihan. Skor sebelum 30 Nov atau tanpa `packStart` tidak berubah.
  - `packStart` = Senin minggu pertama main, disimpan di setiap skor berpaket, dan dicatat sekali di `packStarts/{uid}_{packId}` (dibuat bersama skor pertama dalam satu `writeBatch`, tidak bisa diubah siswa; aturan mencocokkan keduanya dengan `getAfter`). Untuk paket yang sudah dimainkan sebelum aturan ini, minggu pertama = minggu skor paling awal siswa di paket itu (pilihan A pemilik), minimal `FIRST_WEEK`.
  - Klien (`packStartFor` di game-scores.js) mengambil minggu pertama dari riwayat skor yang sudah dimuat (tanpa baca tambahan). Riwayat tidak siap dalam 3 detik: baca catatan `packStarts` (1 baca); tidak ada: minggu ini. Ditolak karena riwayat kedaluwarsa (paket baru dimainkan di HP lain): baca catatan, kirim ulang sekali.
  - Tampilan: `PRACTICE_TEXT` = "Latihan: poin paket ini sudah habis" sebagai tag abu-abu (`.tag.practice`) di daftar paket & pratinjau (`loadPracticePackIds()`), baris hasil `free` di kartu hasil, dan notifikasi. Kartu Beranda "Paket minggu ini" tidak menghitung paket latihan. Paket yang sudah poin penuh: kartu hasil & pratinjau menulis "Poin bisa didapat lagi Senin." jika minggu depan masih berpoin, atau "Minggu depan paket ini menjadi latihan." jika minggu ini minggu terakhirnya (`nextWeekPointsText`, minggu pertama dari `loadPackStartWeeks()`); Beranda saat semua penuh: "Semua paket sudah poin penuh. Tunggu paket baru." Aturan poin di Peringkat (tombol "i"), catatan di halaman game, dan "Semua tier" menyebut batas 2 minggu.
  - Biaya: 0 baca tambahan di Peringkat/Beranda/Toko; per skor berpaket +1 baca di aturan (`getAfter`), +1 tulis saat pertama kali main sebuah paket.
  - Paket lama yang ingin berpoin lagi = buat paket baru (salinan); mengubah paket yang sama tidak mengulang hitungan.
- Siswa melihat paket aktif untuk jenjangnya + paket "Semua jenjang". Aturan Firestore menolak skor berpaket jika paket nonaktif, beda jenjang, atau `total` tidak sama dengan jumlah soal paket.
- Keterbatasan: jumlah jawaban benar tetap dihitung di browser siswa (tanpa server), jadi siswa yang sangat paham teknis masih bisa memalsukan nilai di satu paket, tetapi tidak bisa lagi menumpuk poin tanpa batas.

## Halaman game kosakata

- Tata letak: PC dua kolom (kiri pilih soal; kanan pratinjau + pengaturan + Mulai), HP satu kolom. Kelas `app wide`, `setup-grid`, `side`, `narrow` di `game-ui.css`.
- Kotak cari & filter muncul otomatis jika paket ≥ 6 atau ada lebih dari satu jenjang/level.
- Batas waktu: saran = jumlah soal × detik per soal (Kuis 8, Kartu 12, Hafalan Tanpa Salah 15, Kata Kerja 20, Susun Kalimat 25, Cocokkan Pasangan 6), dibulatkan ke menit (1–30). Default aktif di Kuis & Kartu, mati di Hafalan Tanpa Salah. Waktu habis di Hafalan Tanpa Salah = belum tuntas, skor tidak disimpan.
- Titik merah di depan judul paket = paket belum pernah dimainkan siswa di game mana pun; hilang setelah skor paket itu tersimpan.
- **Poin paket minggu ini** (`packMaxPoints` di `ec-common.js` = jumlah soal × bobot level × bobot game tertinggi; `loadWeekPackPoints` di game-scores.js = poin terbaik siswa per paket minggu ini): tag "Poin penuh" (hijau) atau "16/40 poin" di daftar paket & pratinjau, plus kalimat di pratinjau ("maks. x poin", "x dari y", "Poin penuh ... bisa didapat lagi Senin"). Beranda: kartu "Paket minggu ini" (Poin penuh x dari y paket, bilah, "Masih bisa tambah x poin" / semua penuh → tunggu paket baru atau Senin). Notifikasi simpan skor menampilkan poinnya. Skor siswa & daftar paket dimuat sekali per halaman (dipakai bersama lonceng), jadi tanpa tambahan baca Firestore.
- Pilihan siswa (paket, kata sendiri, pengaturan) diingat di browser (`localStorage`, kunci `ec-k2`, `ec-k2-settings`, dst.).

## Cara menyambungkan game ke skor & papan peringkat

1. Sebelum `</body>`: `<script type="module" src="game-scores.js"></script>`
2. Saat permainan selesai:
   ```js
   window.saveGameScore?.({
     gameId: "id-game-unik", gameName: "Nama Game",
     correct: 8, total: 10,          // wajib, bilangan bulat, correct <= total <= 1000
     points: 950, mode: "timed",     // opsional
     packId: paket.id, packName: paket.title, // wajib agar masuk papan peringkat
   });
   ```
   Daftar paket: `const hasil = await window.loadQuestionPacks("kosakata")` → `hasil.status` (`ok`/`login`/`inactive`/`error`) dan `hasil.packs`. Untuk game kosakata cukup pakai `mountWordSource` dari `word-source.js` (contoh: `kosakata 5.html`); `source.scoreInfo()` mengisi `packId`/`packName`.
3. **Bobot poin = level paket × jenis game** (`scorePoints` di `ec-common.js`, mulai minggu `WEIGHT_FROM_WEEK` = 2026-11-02; sebelumnya 1 jawaban benar = 1 poin). Level (`LEVEL_WEIGHT`, dari `packTier` di skor): Level 1–2 = 1, Level 3–4 = 2, Level 5 = 3, paket tanpa level = 1. Game (`GAME_WEIGHT`): menulis/menyusun (Kuis Kosakata, Kartu Hafalan, Hafalan Tanpa Salah, Kata Kerja, Susun Kalimat) ×2, memilih (Cocokkan Pasangan, Pilihan Ganda Cepat) ×1. Contoh: paket Level 3 di Kuis Kosakata = 4 poin per kata. Game baru wajib ditambahkan ke `GAME_WEIGHT` (tanpa entri = ×1). Level disimpan di skor saat dimainkan (`scoreInfo()` → `packTier`), dicek aturan Firestore agar sama dengan level paket; guru mengubah level paket tidak mengubah skor lama. Winrate/akurasi sengaja **tidak** dibuat: mengulang paket justru didorong (hanya hasil terbaik yang dihitung). Hanya dari paket soal, hasil terbaik (setelah bobot) per paket per minggu, dari game mana pun. Poin = XP = koin, jadi bobot juga mempercepat tier & koin (batas tier/harga toko mungkin perlu disesuaikan). Minggu dihitung Senin 00.00 – Minggu 23.59 WIB.
4. Skor hanya tersimpan jika siswa login dan profilnya masih ada. Jika tidak, muncul notifikasi kecil.
5. **Baris poin di kartu hasil** (Paket A tinjauan UI): kirim `resultEl: document.querySelector("[data-score-line]")` ke `saveGameScore` (elemen `<div class="score-line" data-score-line hidden>` di kartu hasil; gaya `.score-line` + `gain/same/full/free/trial/info/err/wait` di `game-ui.css`). Isi baru muncul setelah skor **tersimpan**: "+x poin" (+ "Total paket ini minggu ini: a dari b" / "Poin penuh"), "Hasil terbaikmu masih x poin", "Belum dapat poin di paket ini", "Poin penuh" (sudah penuh sebelum main), "Latihan bebas: tanpa poin", "Mode coba: skor tidak disimpan" (guru), Tantangan Harian "+x poin" / "sudah tersimpan sebelumnya" (dicek: dokumen harian ada) / akses ditolak / koneksi. Kenaikan = poin baru − hasil terbaik paket itu minggu ini (`scorePoints`, sama dengan `weeklyPoints`), dari riwayat yang sudah dimuat (tanpa baca tambahan); riwayat belum siap/gagal → "Skor tersimpan. Lihat poinmu di Beranda." Riwayat di halaman diperbarui setelah setiap skor tersimpan. **Offline:** Firebase menunggu (tidak langsung gagal); jika 8 detik belum ada jawaban → "Internet belum tersambung. Jangan tutup halaman ini, skor akan disimpan saat internet kembali.", lalu otomatis diganti hasil poin begitu tersimpan. Skor dikirim sekali saja (tidak diulang). Tantangan Harian langsung menampilkan kartu hasil dengan baris ini. Jika `resultEl` dipakai, notifikasi pojok tidak muncul. Hasil kembalian: "ok" / "exists" / "denied" / "error".

## Data Firestore

- `users/{uid}`: name, role "Student", email, level, classCode, loginType ("email"/"username"), createdAt, lastLoginAt, announceSeenAt (terakhir menekan "Mengerti" di pengumuman)
  - Profil **guru** (dibuat admin di tab Guru): name, role "Guru", active (true/false), email (email asli), loginType "email", createdAt, lastLoginAt. Tanpa level & classCode. Profil tanpa field role dianggap siswa (siswa lama).
- `classCodes/{KODE}`: level, note, active, createdAt
- `questionPacks/{id}`: title, type ("kosakata"/"verb"/"kalimat"), level (jenjang atau "SEMUA"), tier (1–5, opsional untuk paket lama), active, items[], itemCount, createdAt, updatedAt, publishedAt (diisi saat dibuat & saat diaktifkan lagi; dasar notifikasi, paket lama memakai createdAt; null untuk draf), ownerId? (uid guru pembuat; tanpa = paket admin), draft? (true = draf guru). Untuk pemeriksaan admin nanti cukup tambah satu field (mis. `review`)
- `announcements/{id}`: title (≤80), body (≤2000), level (jenjang atau "SEMUA"), active, createdAt, updatedAt, publishedAt (diisi saat terbit, saat diaktifkan lagi, atau saat diubah dengan centang "Tampilkan lagi")
- `weeklyResults/{week}`: week, ranking [{uid, name, level, points, packs, rank}] (papan Semua Jenjang; papan jenjang = `levelRanking`), players, savedAt. Hanya admin yang menulis
- `gameScores/{id}`: userId, userName, gameId, gameName, correct, total, percent, points?, mode?, level?, packId?, packName?, packTier? (level paket 1–5 saat dimainkan), packStart? (Senin minggu pertama siswa main paket ini; wajib untuk skor berpaket sejak aturan 26 Nov 2026), daily? (tanggal Tantangan Harian; ID dokumen harian-<tanggal>-<uid>), week ("YYYY-MM-DD" Senin; aturan: harus minggu ini, kelonggaran 1 jam setelah Senin 00.00 WIB), timestamp
- `packStarts/{uid}_{packId}`: userId, packId, week (Senin minggu pertama main), createdAt. Dibuat siswa sekali; hanya admin yang mengubah/menghapus (ikut terhapus saat admin menghapus akun)
- Akun tanpa email memakai email sintetis `<namapengguna>@siswa.extra-course-d02c2.firebaseapp.com`.

## Preferensi pemilik

- Tampilan harus **rapi di HP dan PC** (cek kedua ukuran, juga mode gelap). Suka tampilan Monitor Kelas (hijau, kartu simetris, kotak cari jelas).

- **Kabari pemilik** jika suatu fitur butuh upgrade berbayar atau layanan pihak lain (mis. server/Cloud Functions Firebase).

## Keterbatasan yang diketahui

- Kuota gratis Firestore 50.000 baca/hari. Beranda & Peringkat membaca semua skor minggu ini setiap dibuka; lonceng & riwayat membaca semua skor milik siswa. Aman untuk puluhan siswa; jika siswa aktif mendekati 80–100, perlu penghematan (simpan ringkasan, jangan hitung ulang dari nol). Cek di Firebase Console → Firestore → Usage.

- Password akun nama pengguna tidak bisa direset dari website (Firebase gratis, tanpa server).
- Hapus akun dari admin menghapus profil + skor; akun login terhapus saat siswa mencoba masuk lagi.
- Skor sebelum fitur peringkat tidak punya field `week`, jadi tidak dihitung di papan peringkat.
- Skor tanpa `packId` (semua skor sebelum fitur paket soal) tidak dihitung di papan peringkat.
